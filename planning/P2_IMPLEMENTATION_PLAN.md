# P2: Memory, Sources and Dark Mode

Proposed implementation plan, 2026-10-15; revised for forget/history eligibility, library-wide limits and distinct QA identity. This document defines proposed work packages, not completed functionality or approval of unselected dependencies. Preserve the local-first mascot assistant and the existing shared drawer/full-app conversation. Release packaging and the current QA memory policy follow [recorded decisions](DEFERRED_ISSUES.md).

## Accepted Execution Contract (2026-10-18)

- Implement the remaining stages as one delivery without intermediate approval checkpoints. Existing permission and device-safety boundaries still apply; this does not authorize commits, pushes, data resets or weaker safeguards.
- Prove tokenizer/budget viability, vetted authenticated streaming storage with protected PDF access, and embedding allocation/cancellation/handoff before dependent behavior. Failed gates block their dependents. Do not enlarge the 2048 context or reduce the 512 output reservation to bypass a gate.
- Write and run focused prerequisite/regression tests during development, then run one consolidated final acceptance campaign over the completed experience. The additional standalone native smoke remains deferred to that campaign. Compilation alone is not runtime proof.
- Query embedding belongs to the foreground reply. One generation ID and reservation spans eligible context, query embedding, retrieval, confirmed encoder release, Gemma admission and generation. Release resident Gemma before admitting the encoder unless concurrent residency has separately passed verification. Background indexing must not enter the reserved encoder-to-Gemma handoff.
- Stop signals the active native owner out of band. Subsequent native work requires confirmed cleanup; uncertain cleanup quarantines the owner and requires restart. Models-panel load/unload/benchmark requests return BUSY during a foreground reservation; panel Cancel cannot cancel another owner's request.
- The five-second retrieval deadline includes queueing, resource reclamation, cold encoder loading, query encoding, retrieval and encoder release, but excludes Gemma loading/generation. Timeout produces a typed error and initiates cleanup; it does not imply instantaneous native cleanup. Record cold/warm paths separately. Revise an unmet contract explicitly before enabling semantic retrieval.
- Use a vetted authenticated-streaming implementation, not a new cryptographic protocol. Version the format and authenticate scheme/key version and document/revision binding. Bound read sizes, decrypted cache, open handles and cancellation. Complete a bounded-memory authentication pass before PDF parsing; subsequent seeks also authenticate their data. Never expose unauthenticated plaintext or write plaintext temporary PDFs. Corruption, truncation, wrong keys, reordered/duplicated chunks and cross-document/revision substitution prevent publication and remain recoverable storage errors, never a reason to reset data.

Appearance/QA identity and targeted native supervision loss/recovery are already implemented; their remaining manual acceptance checks remain open. No new source, memory or retrieval feature is marked complete by this execution contract.

## Outcome and Scope

Make Memory and Sources usable: explicitly import text and text-based PDFs, inspect extracted evidence, search locally, ask source-grounded questions with resolvable citations, and create/correct/forget personal memories. Add consistent System/Light/Dark appearance across the app and both conversation hosts, plus a clearly distinguishable QA app icon and name.

No OCR, scanned-PDF interpretation, image understanding, speech transcription, expenses, device actions, external account connections, cloud inference or automatic personal-memory extraction in this phase. OCR/receipt work remains P5; speech remains P3. Images/audio retain their existing storage and preview behavior without implying interpretation. Deferred audio consent/dictation behavior is unchanged.

Record artifact/tokenizer/template identities and validate Unicode, control-marker rejection and actual native token counts against the chosen contract.

Define explicit sub-budgets for the question, retained complete turns, confirmed memories, evidence labels/passages, role/template overhead and response. Truncate only at validated text/token boundaries; never discard the current question silently.
- Produce an immutable `GroundedRequest` snapshot with the allowed source-revision/chunk IDs and spans plus the captured context-eligibility epoch. Apply the persisted history-eligibility fence before whole-turn selection, budgeting and retrieval, on ordinary chat as well as grounded requests and retries. ## P2-03: Persistence and Bounded Import

- Extend the existing encrypted SQLDelight database with Source, SourceRevision, IngestionJob, SourceChunk, Embedding, Memory/Provenance, message-citation relationships, durable context-eligibility epochs/fences and quota reservations/counters. Preserve existing message IDs, roles, attempts, attachments, draft epoch and search results through migration tests. Persist selected source IDs separately from file attachments; do not overload draft epoch with forget/delete semantics.
- Repositories own durable sources and memories; exposed state is immutable Flow, and one-shot operations are main-safe suspend APIs. Keep portable job/revision/deletion rules in common code. Android owns picker/provider access, PDF extraction, crypto/filesystem and native embedding adapters.
- Add bounded streaming to protected document storage; do not route large documents through the current whole-byte-array attachment API. Stage uniquely named encrypted files, validate size/type/content hash, promote immutable versions and reconcile DB/file divergence after interruption. Personal extracted text, chunks, vectors and thumbnails remain protected, with backup exclusions and no plaintext debug exports.
- Proposed first limits: 20 MiB per file, 100 PDF pages, 500,000 extracted characters per source, 2,000 chunks per source and one active ingestion job. Enforce before and during processing, including provider streams with unknown/false size. Confirm/revise these limits during the parser spike before enabling import; low disk, malformed/oversized and password-protected PDFs fail with typed recoverable states.
- Support explicit pasted text, UTF-8 plain text and text-based PDF import through Sources. Reuse system picker integration without changing unsent composer attachments automatically into library items. Offer an explicit Add to Sources action for eligible existing attachments, preserving the original relationship and bytes.
- PDF parser selection must prove extraction, page mapping, supported ABIs/license, bounded memory/time and encrypted-input compatibility. If a parser needs seekable plaintext, solve that explicitly within the protected-storage design before accepting it; do not silently create unencrypted temporary PDFs. Scanned/no-text pages report that OCR is unavailable in P2, not successful analysis.
- Deduplicate by content hash without conflating different ownership/revisions. Persist stages/checkpoints: importing, extracting, chunking, keyword-ready, embedding, ready, paused/cancelled and failed. Cancellation releases file/parser handles and removes uncommitted staging data. Reopen reconciles unfinished jobs and resumes only from verified checkpoints/private copies.
- Start with a foreground-owned, checkpointed queue; define pause/resume on host loss explicitly. Do not claim work survives process death merely because its job row survives. Add OS background scheduling only if requirements justify it, without adding an always-on inference service.

### Library-Wide Quotas and Reservations

The following are proposed first-version ceilings, not verified capacity claims. Confirm/revise the numeric values in the ingestion/embedding spike before enabling library growth; all ceilings apply together, and hitting one does not permit exceeding another.

| Resource | Proposed ceiling |
| --- | --- |
| Source identities / retained source revisions | 500 / 1,000 across the whole library |
| Stored source chunks | 20,000 across all retained revisions |
| Stored vectors | 20,000 across source and memory indexes and all retained encoder versions |
| Vector payload | 64 MiB serialized total and 64 MiB declared decoded-size total; enforce both from validated dimensions/encoding without decoding the full index |
| Confirmed/proposed memory records | 1,000 combined |
| Import/indexing storage admission | 512 MiB combined across protected library files and the shared personal DB/WAL/journal footprint; model weights are excluded |
| Pending/paused ingestion jobs | 10 total, one active worker; keep at most 100 terminal job metadata records |

- The storage admission check includes encrypted originals, retained/citation-pinned revisions, extracted text, chunks, FTS/vector structures, staging, replacements/reindex copies and deletion-pending files. Count the shared DB conservatively rather than pretending its per-feature physical pages can be measured exactly. Existing conversation/attachment data is not evicted to admit imports; unrelated conversation growth can consume the remaining headroom and must pause new P2 growth, not silently delete chat or expand the budget.
- Add a separate 512 MiB free-device-storage reserve after projected growth. Preflight both the quota and disk reserve, then atomically reserve bytes/rows/jobs under the ingestion owner before copying or indexing. Unknown provider lengths reserve the allowed maximum. Recheck actual bytes, DB/WAL growth and row counts during bounded stages/transactions; reject before the next allocation/commit would exhaust the reservation. The spike must establish conservative encrypted-file/index/transaction overhead bounds; logical text size alone is not a physical-storage bound.
- Replacements and encoder upgrades reserve old plus new representations until cleanup is confirmed. Stale vectors, failed staging and pending-delete bytes remain charged while present. Shared-file deduplication releases storage only after the final reference is removed. Quota errors are typed, keep prior valid sources intact and expose cleanup/cancel/retry; there is no automatic eviction of personal sources, memories or cited revisions.
- Count reservations, retained/stale revisions, obsolete vectors and pending-cleanup records against the relevant row ceilings until released transactionally; copying the same source through a different intake path does not create an unaccounted budget. Report usage and which ceiling blocked growth, without claiming that existing conversation writes are globally capped by the P2 import policy.
- Reconcile reservations/counters against actual protected files and database state after crashes before admitting new work. Persist a blocked/quota state if capacity cannot be established. A source may remain keyword-ready when embedding growth is blocked; it must not be marked semantic-ready. Do not interpret an interrupted reservation as free space.

## P2-05: Local Embeddings and Hybrid Retrieval

- Select the embedding artifact/runtime in a separate spike. Pin exact bytes/hash/revision/license, tokenizer, pooling, dimensions, normalization and query/document formatting. Verify installation, repair, CPU/backend behavior, offline use, incremental peak allocation and cancellation on S24. Do not assume Gemma chat weights are an embedding encoder.
- Preserve the existing runtime owner. Add only the shared resource arbitration needed for chat versus indexing: active capture/user reply outranks requested source processing, which outranks background indexing. Pause/release lower-priority native work before admitting higher-priority work; avoid simultaneously resident GPU sessions unless separately measured and approved.
- Chunk by paragraph/page boundaries using the selected encoder's tokenizer limits. Store embedding identity on every vector; never compare mixed versions/dimensions. Model changes mark old vectors stale and trigger recoverable reindexing.
- Combine encrypted keyword search with exact vector similarity at the reference corpus size, rank/deduplicate and bound candidates before prompt assembly. Do not add an ANN/vector extension until measured need and SQLCipher compatibility are established.
- Bound query working sets independently of library size: library lists use keyset pages of at most 50 rows; FTS returns at most 50 scored IDs, not full source bodies. Exact vector scoring scans stable revision/encoder snapshots in batches of at most 128 vectors and 2 MiB decoded vector payload, whichever comes first, retaining a top-50 score/ID heap rather than materializing the index. Merge/deduplicate at most 100 candidates, rerank at most 20, fetch text in batches of at most 8 chunks and at most 64 KiB total decoded candidate text per query, then admit at most 4 evidence passages subject to the stricter verified prompt budget. Memory retrieval contributes at most 20 candidates and shares the same final context budget.
- Check cancellation and source/context epoch changes between batches; cap each retrieval operation at 5 seconds with a typed timeout/narrow-selection result. An incomplete vector scan must not be presented as an exact library-wide top result. Snapshot/cursor state may not resurrect deleted content. Bound open cursors and temporary arrays; do not load the full corpus or vector table into Kotlin collections.
- Keyword search remains usable when embedding assets are absent, with semantic search visibly unavailable. A degraded lexical-only result is not reported as semantic readiness. Installation/indexing does not silently download model assets.
- Proposed performance gate: 100 synthetic sources/2,000 chunks, p95 keyword query <= 1 second and hybrid retrieval <= 2 seconds, excluding LLM generation. Use at least 20 measured queries per cold/warm case on S24; record corpus, tokenizer/model versions, failures and sampled memory. These are targets, not current measurements; review revisions explicitly.
- Also measure at the maximum admitted chunk/vector/byte capacities and test quota boundaries. If a complete exact scan cannot satisfy the bounded query contract, revise the advertised capacity/index strategy explicitly before enabling that capacity; do not hide truncation or validate only the smaller reference corpus.

## P2-07: Explicit Personal Memory

- Replace the placeholder with confirmed memories, optional pending suggestions, search/filter, edit, origin/provenance, correction and forget. Create from explicit user entry or a reviewed selection from a message/source. An assistant statement or quoted speaker preference does not become a user fact automatically.
- Define a stable memory ID, revision/status, timestamps and provenance links. Corrections supersede the old fact and remove old searchable/vector representations before future recall. Explicit confirmation gates any model-proposed write; ambiguous Remember/Forget requests open a review rather than execute guessed changes.
- Retrieve only confirmed, valid memories. Respect topic/relevance and the same bounded context contract; never inject the entire memory store. User edits/deletes invalidate active context and late completions as source changes do.
- Forget deletes the active fact and its derived indexes. History visibility and model-context eligibility are separate persisted decisions: preserved historical quotations must not remain automatically eligible for later prompts. Explain that Forget removes saved recall and stops prior chat-context reuse without necessarily erasing visible chat; offer separate linked-history removal. Clearing conversation history does not silently delete the source library or confirmed memories.

### Forget/Delete Context Eligibility

- Use a conservative first-version rule: every memory forget/correction or source deletion/replacement advances a durable context-eligibility epoch and fences off all pre-existing chat messages from automatic prompt reuse across conversations. Whole user/assistant turns remain visible unless separately deleted, but become ineligible for recent-turn context, semantic/history recall, summaries and automatic memory suggestions. This intentionally sacrifices older automatic conversational context rather than claiming complete semantic detection of every quotation/paraphrase. Explain the context reset at confirmation time.
- Invalidate derived conversation summaries and history embeddings covering excluded messages, including uncited paraphrases. Do not rely only on citation/provenance matching or string matching. Enforce eligibility at every prompt/retrieval boundary, including ordinary chat, follow-ups, restart reconstruction, selected sources and retry. Disable retry of an ineligible old user turn; visibility or opening a historical search result is not permission to feed it back to inference.
- A forgotten memory's recorded source provenance also becomes ineligible for automatic recall; exclude its containing chunk/revision if a smaller safe span cannot be isolated. Preserve source visibility separately. A corrected memory records the user's new assertion rather than treating its superseded source statement as supporting the new value. Define the confirmation scope as the selected record/provenance plus prior chat context, not an unverifiable semantic purge of every independent document containing similar information.
- Coordinate mutation through an admission barrier shared with the existing session: revoke active generation identity, atomically persist the epoch/fences and deletion/correction/index invalidation, then cancel/discard in-flight output and safely release its native conversation. Completion transactions must compare the captured epoch, not just current source existence. Admit new work only after native quiescence/cleanup is confirmed; uncertain cleanup requires existing restart/quarantine recovery. A process death between these steps must not restore old eligibility or partial output.
- Preserve only minimal opaque IDs/epochs/reason metadata for invalidation, not a plaintext copy of forgotten facts as a blacklist. Independently confirmed, still-valid memories/sources remain eligible under their own revision and relevance rules. New text explicitly submitted by the user after the fence may reintroduce information, but merely reopening/retrying old content, reindexing, or a late callback may not. Existing unsent drafts remain unsent and must never be automatically submitted.
- The guarantee is exclusion from app-managed future context, not erasure from pretrained model knowledge or from visible records the user chose to retain. If historical text itself must be removed, use the separate history-deletion action. Neither operation promises forensic storage erasure.

## P2-08: Deletion, Recovery and Acceptance

- Transactionally tombstone deleted/replaced sources and invalidate chunks, vectors, dependent generated summaries and source-backed memories; perform retryable encrypted-file cleanup afterward. User-authored independent memories are not removed merely because another source mentions the same fact. Exclude tombstoned content immediately from retrieval, even before file cleanup finishes.
- Reconcile interrupted imports/indexing, metadata/file promotion, storage exhaustion, stale provider permissions, missing assets, key loss and reindex failure. Never silently reset encrypted personal storage. Preserve existing attachment/history semantics and do not claim forensic flash erasure.
- Keep diagnostics synthetic/metadata-only. Verify encryption coverage for FTS, vectors, files, journals, temporary processing and logs; test clear/delete/reopen and backup exclusions. No provider content, receipts, keys, private DB exports or personal screenshots in test reports.
- Common tests: budgeting, retrieval ranking/filtering, memory confirmation/correction, revision invalidation, scheduling, cancellation, clear/delete/completion races and stale callbacks. JVM SQLDelight tests: migrations, indexes, transactional provenance/citations, idempotency and interruption reconciliation. Android tests: bounded provider/PDF/crypto adapters, preferences and lifecycle. Compose tests: theme resolution, empty/error/indexing states, citation navigation and host-state preservation.
- Forget/delete regressions must keep old user/assistant quotations and uncited paraphrases visible while proving they are absent from subsequent ordinary/grounded prompts, retrieval, summaries, retry and suggestions, including after reopening/process death. Cover mutation-versus-completion races, correction of an old fact, failed native cleanup, explicit new user reintroduction and independent valid memories. Inspect fake-runtime request snapshots, not only rendered answers.
- Quota/batch regressions cover each global count/byte limit, simultaneous reservations, unknown-length input, false provider sizes, mid-copy/index exhaustion, retained revisions, reindex overlap, pending cleanup, deduplicated references, crash reconciliation and unrelated chat growth. At maximum capacity assert vector/text batch sizes, candidate heap limits, SQL page limits, cancellation/deadlines and no full-table materialization. Rejected work must not damage existing data or admit partial semantic readiness.
- Retrieval/grounding fixture gate: 50 answerable and 20 unanswerable questions, >= 90% supported answers on the answerable set, >= 95% abstention on unanswerable fixtures, and 100% returned citations resolving to allowed live revision/spans. Include contradictions, irrelevant sources, Unicode, prompt-injection text, deleted sources and corrected memories; citation resolution alone does not satisfy factual support.
- S24 acceptance: import -> inspect -> ask -> follow-up -> citation -> remember -> correct -> forget -> reopen. Exercise process death/reboot, offline operation with assets installed and traffic observation, dark/light/system switching, accessibility, resource-pressure failure and foreground/host transitions. Repeat the supervised 20-minute workload with actual retrieval/indexing arbitration; the LLM-only pass does not certify this mixed workload. Unplugged battery comparison needs a suitable supervised connection arrangement; USB percentage endpoints are not an energy benchmark.
- Record passed, failed, blocked and not-run separately. A green P2 fixture run does not close deferred release packaging, audio consent or untested device claims. Keep normal app memory policy and QA experiment scopes explicit in every native report.
