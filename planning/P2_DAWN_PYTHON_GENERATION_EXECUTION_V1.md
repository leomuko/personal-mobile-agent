# Python/generation subset execution, v1

Implements the independently reviewed `python-generation-cpp-blocked-v1` amendment
in `P2_DAWN_PYTHON_PATCH_QUALIFICATION_V1.md`. This profile does not qualify the
complete dependency recipe, callback semantics, Bazel Python selection or Android.

## Fixed sequence

1. Revalidate the successful R3 preparation receipt, source/runtime specifications,
   all fifteen OS-cache identities and inspection tools. No compiler is admitted.
2. Acquire exactly the two URLs in `candidate-inputs.json`, no retries/redirects.
   Verify exact sizes/SHA-256 before ZIP parsing, then CRC, paths, metadata, tags,
   dependency declarations and complete RECORD coverage. Inactive Babel is retained
   as declared metadata; no extras selected, no Babel acquisition.
3. Materialize the private runtime with the 101 declared transformations and no
   other byte changes. Stage both packages by verified member hashes, without pip.
   Resolve the MarkupSafe extension's Mach-O closure against the same pinned OS.
4. Copy the 105 qualified generator source files. The 26 checked-in C++ headers
   remain outside execution in this no-compiler profile; their frozen inventory is
   preserved for the future blocked C++ branch.
5. Before candidate code, exercise the frozen sandbox using trusted host Python:
   an owned write succeeds; a unique outside-attempt sentinel write and loopback
   connection to `127.0.0.1:9` must fail with EPERM. No remote service is contacted.
   Failed enforcement blocks candidate execution; no unrestricted retry.
6. Run candidate Python `-I -S -B` through the same network/write-denying sandbox.
   Check interpreter facts, native speedups, module origins and exact synthetic
   escape/Unicode/autoescape/include/inheritance/do/loopcontrols results.
7. Execute the three exact `-c` programs from the preserved patch manifest once
   each, in the private candidate source base. Require every pre/postimage and
   match count. Other source files and the source inventory remain unchanged.
8. Clone independent control/candidate workspaces for each of two repeats.
   Execute `headers`, then `cpp_headers`, in each workspace: eight invocations.
   Generator argv uses exactly the pinned relative source/template paths and
   `_out` output path. Preserve all workspaces, reports and outputs. Require all
   eight outputs to reproduce; six equal control; both affected headers equal the
   frozen six literal transformations. Reject additional files or source changes.
9. Revalidate the original preparation and frozen inputs. Record each stage,
   including NOT_RUN stages after the first failure, and owned-process cleanup.

No code repair, output normalization, dependency substitution, retry, compiler,
SDK build, Bazel or device workload is admitted. A failure remains a failure.

## Bounds and publication

The unchanged whole decision limit is 300 seconds plus at most 15 seconds owned
cleanup. Each vendor command is at most 30 seconds; inspector commands 15 seconds;
HTTP acquisition at most 15 seconds each. Peak worker RSS 512 MiB, total attempt
writes 512 MiB, fresh free space at least 1 GiB. Check complete attempt size at
command boundaries; the reviewed source and fixed output manifest bound expected
writes. This is not a filesystem quota or an adversarial-code execution service.

Split the combined 2 MiB log allowance into 1 MiB owned worker stdout/stderr and
1 MiB encoded child trace. Each child capture is at most 512 KiB. Stage/result
JSON remains capped at 32 MiB each. Runtime/member/index bounds remain unchanged.
All child processes inherit the outer owned process group. A failed or timed-out
command is terminated and outer cleanup must be confirmed before any acceptance.

Exit 0 is reserved for a successful private worker, not overall qualification.
The public runner returns 2 only when the admitted Python/generation subset passes
and cleanup is confirmed; its `accepted-subset.json` states `recipeQualified=false`.
It returns 1 on admission, execution, output or cleanup failure. C++ tests remain
BLOCKED/NOT_RUN even after subset success: 6 positive compiler commands, 6 runs,
12 negative compiler commands. No callback-behavior or language-compatibility
credit follows from byte comparison.

The separate 18 GiB analysis floor is unchanged. No global package changes,
evidence deletion/relocation, Git operations or semantic-search enablement.

## Review gates

The implementation and immutable execution freeze require independent QA before
acquisition or candidate execution. Preparation results require their own review.
The same sole QA reviewer is reused. Results will be reviewed independently after
the single admitted attempt; any failure stops dependent behavior.

## Whole-invocation deadline correction (R2)

R1 is retained and not executable: independent QA reproduced public acceptance at
350 seconds after a worker succeeded at 299 seconds. R2 starts the monotonic clock
before public admission, passes the original absolute deadline to the worker, and
budgets every child/HTTP call against its remaining time. Final input checks,
report parsing, size scans, receipt/outcome serialization and publication are all
qualification work under the original 300-second decision limit. The 15-second
cleanup allowance never grants more qualification time or permits late success.

Check immediately before and after both public hardlink operations. If a link
operation crosses the deadline, revoke only those fresh public links after
confirming their pending-file identity. Keep both pending serializations and write
a failed terminal outcome; this revokes acceptance without deleting evidence.
No accepted receipt is published for delayed admission, delayed final validation,
slow serialization, late cleanup or late publication. No timeout retry is admitted.

## Interrupted publication correction (R3)

R2 remains preserved and unexecuted. Independent QA found that an interrupt after
hardlink creation, before tracking that link, could leave acceptance present while
claiming revocation. R3 registers each publication intent before its interruptible
syscall. Failure cleanup examines every intended link by its pending identity,
continues revoking other owned links if one identity is foreign, and preserves all
pending bytes and foreign/prior files. Terminal flags report actual acceptance
presence and confirmed versus uncertain revocation; no unconditional success flag.
Interrupted-after-effect tests cover both links, plus preservation of a foreign
public file. Deadline limits and admitted work remain unchanged.

## Host clock-origin correction (R4)

The single R3 attempt stopped at worker admission, before any download, candidate
or vendor execution. Cleanup was confirmed; no public acceptance exists. Preserve
`qualification-attempts/python-1/` unchanged. This is infrastructure failure, not
wheel/Python/generator quality evidence.

The pinned host CPython3.9 on macOS uses process-relative `time.monotonic()` origins.
Transferring that absolute value to a new process is invalid. R4 uses the existing
stdlib POSIX `time.clock_gettime(time.CLOCK_MONOTONIC)` clock in both parent and
worker. A bounded trusted-host subprocess proof requires the child's reading to
fall between parent before/after samples. No Java/Python upgrade, dependency or
limit change. Internal child elapsed-time measurements do not transfer epochs.

A reviewed R4 freeze may admit one fresh infrastructure-corrected attempt, with
all earlier evidence retained, no HTTP/vendor retry inside that attempt, unchanged
300-second whole decision/15-second cleanup limits and unchanged Python-only
scope. Review the failed launch, clock proof, implementation and new freeze before
any acquisition. All C++/Bazel/device exclusions remain in force.
