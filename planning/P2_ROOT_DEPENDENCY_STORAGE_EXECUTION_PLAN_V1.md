# Root-closure storage and execution plan v1

2026-11-02. Proposal only. Current free space is about 2.7 GiB. No new analysis
can pass the existing **18 GiB** preflight. No automatic deletion, compressed
replacement or relocation of retained evidence is authorized.

1. **Finish source qualification separately.** The failed bounded v1 inspection
   is preserved. Review the offline v2 proposal before implementation/execution.
   Its 512 MiB output-byte reservation and 1 GiB minimum free-space check permit
   a small source-data step; they do not authorize analysis or native adoption.
2. **Inventory and reserve complete new inputs.** Once the archive is qualified,
   use its measured expanded bytes and member counts, wheel bytes, immutable
   patch/bridge files and cache-copy requirements. Include staging, accepted
   copies and failed work, not just compressed archive size. No guessed-complete
   Dawn, Python or transitive recipe.
3. **Resolve capacity by an explicit user choice.** The user may free unrelated
   space or authorize hash-verified archival relocation to another volume. Keep
   original manifests, outcome/FAIL history and a relocation map. Old absolute-
   path execution freezes remain historical; any relocated execution needs new
   reviewed paths. Never rewrite an old freeze to claim it still authorizes a run.
4. **Plan three complete roots.** The prior warmed attempt left about 2.8 GiB
   free after setup of root plus both ABI outputs. Reserve the previous footprint
   plus three copies of newly required expanded Dawn inputs, staged SDK workspaces,
   accepted/writable cache copies, wheels, temporary work and a documented safety
   reserve. Preserve the 18 GiB floor; publish the larger concrete capacity plan
   in the reviewed execution freeze if measured needs exceed it.
5. **After amendment adoption and implementation review**, prepare the root/ABI
   analysis freeze. Keep ARM64/x86_64, GPU/WebGPU paths, private Java-21 server,
   original compilation declarations/locks, 300-second command deadlines,
   15-second cleanup and 16 MiB logs. Disclose initial/working cache states,
   preparation timing, per-command timing and untimed staging explicitly.
6. **Stop at the next blocker.** Retain conflicts, failed commands and uncertain
   cleanup; no deadline change, repository shadow, source upgrade, backend
   reduction or opaque binary substitution. Complete configured graphs precede
   supplier/feature/toolchain checks; separately authorized generated-header and
   numeric/interface probes precede complete runtime build readiness.

No SDK/AAR/APK build, application dependency substitution, emulator/model or S24
work, commit or source adoption belongs to this proposal. Emulator-first remains
the eventual validation order; P2 incomplete and semantic search disabled.
