# P2 Prerequisite Contracts

Date: 2026-10-18. Status: implementation in progress, not P2 acceptance.

## Prompt Budget V2

Keep LiteRT-LM 0.17.1, the pinned Gemma artifact/tokenizer, 2048 context and 512 output reservation unchanged. The model owns text-only USER/ASSISTANT templating; thinking, tools, system and multimodal messages remain disabled.

`gemma4-e2b-byte-bound-v2` uses `128 + sum(96 + UTF8(payloadBytes))`. The previous P1B bound used three times the payload bytes to cover whitespace escaping. The pinned SentencePiece BPE model has identity normalization, no character map, no dummy prefix, no whitespace removal, byte fallback and a NORMAL one-token U+2581 metaspace. Replacing an ASCII space therefore costs one seed, not three byte-fallback seeds. Other valid Unicode scalars cost at most their UTF-8 byte length. BPE merges only reduce the initial symbol count; unused-piece resegmentation undoes merges without exceeding those seeds. The unchanged per-message/template reserves cover the audited SDK role markers and generation prefix. Malformed UTF-16 and reserved control markers remain rejected.

The host verifier now fails closed if the NORMAL metaspace assumption changes. It still verifies the complete model SHA-256 and embedded tokenizer SHA-256 before testing 2,009 single-turn and 1,000 history cases. This proof is artifact/template-specific, not a generic character/token estimate. A single current ASCII message may occupy 1312 bytes at the existing configuration. Grounded prompts must include instructions, labels, evidence and question in that same budget; this does not allocate an extra evidence window.

Shared tests cover exact capacity, overflow, Unicode, whole-turn trimming and a synthetic four-excerpt follow-up. These do not certify source grounding or new S24 native token counts. Existing runtime prefill-count validation remains enabled. Historical P1B results retain their original v1 measurements.

References: [SentencePiece BPE implementation, v0.2.0](https://github.com/google/sentencepiece/blob/v0.2.0/src/bpe_model.cc), [normalization implementation](https://github.com/google/sentencepiece/blob/v0.2.0/src/normalizer.cc), [pinned model manifest](../../planning/models/gemma-4-e2b-it.json).

## Authenticated Document Storage

Use `com.google.crypto.tink:tink-android:1.18.0`, Apache-2.0, with Tink's AES128-GCM-HKDF streaming AEAD and 1 MiB ciphertext segments. No custom cipher or segment-authentication protocol is introduced. The app's 16-byte container header identifies magic, format version, key version and encryption scheme; these bytes plus source/revision identity are authenticated associated data. Opaque, length-delimited IDs prevent path traversal and filename ambiguity. Ciphertext files live in a private no-backup namespace when the repository is wired; titles and extracted text must remain in the encrypted database.

Tink keysets are encrypted with its Android Keystore AEAD integration and authenticated namespace/version binding, then persisted atomically. No cleartext keyset serialization or fallback is used. Missing/corrupt keysets or missing master keys fail without replacing existing content. Key material is not exported in diagnostics. The vault is process-serialized; future isolated workers must receive read-only descriptors, not independently initialize this vault.

The storage adapter streams with a 64 KiB application buffer and caps actual plaintext at 20 MiB even for false/unknown provider sizes. It stages uniquely named ciphertext, finalizes authentication, fsyncs the file and promotes an immutable revision. A per-root in-process mutex plus an OS file lock protect existence-check/rename and deletion across cooperating instances/processes. The empty lock file contains no personal data. Hard-link promotion was rejected by S24 filesystem policy and is not used. Repository quota reservation, directory-durability/restart reconciliation and stalled provider cancellation are still required before exposing import. Existing byte-array attachments are unchanged.

A full bounded-buffer authentication pass completes before publishing a seek reader. At most two readers are open. Seek reads use Tink's authenticated segment cache, not unauthenticated plaintext; cached bytes need not be reread from disk on every seek. The 1 MiB segment choice bounds Tink's decrypted segment cache per reader; this is distinct from its ciphertext buffer and process heap. No full plaintext document array is used by the adapter. Readers must be closed by their owner, including cancellation at dispatcher handoff.

The Android proxy-file-descriptor bridge provides authenticated seek reads without a plaintext temporary file. S24 synthetic PDF extraction works with the API-35 platform parser. This is a protected-input feasibility result, not permission to parse arbitrary PDFs in the app process. Untrusted parsing still requires isolated ownership, bounded time/memory/output, password/no-text/unsupported handling, cancellation and an explicit compatibility decision for API 31-34. The cached PDFBox-Android candidate has not been adopted.

References: [Tink streaming AEAD](https://developers.google.com/tink/encrypt-large-files-or-data-streams), [Tink 1.18.0](https://github.com/tink-crypto/tink-java/releases/tag/v1.18.0), [Android PDF renderer ownership/isolation](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer).

## Encoder Candidate Gate

Gemma remains the chat model. An encoder is a separate, smaller dependency, not a replacement chat model. The initial QA-only candidate is the public version-1 MediaPipe Universal Sentence Encoder artifact (6,120,274 bytes, SHA-256 `89ad3c74175dd8caa398cc22b657296d94302d20c525c12b58b29420f7249749`) with `com.google.mediapipe:tasks-text:1.1.1`. The SDK is Apache-2.0; the upstream USE-QA model is identified as Apache-2.0 in Google's Chromium test-model provenance. Final model/tokenizer/head/pooling/format identities and notices must be recorded before adoption. SDK AAR inspection includes arm64-v8a and x86_64, not runtime certification of either ABI.

The public Java embedding APIs are synchronous and have no cancel method. A coroutine cancellation wrapper is insufficient. The QA spike therefore uses a request-specific isolated process with a Binder parent-death token, scoped stop, five-second worker deadline, resource checks and confirmed Binder death before recovery. The owning app samples the unchanged shared resource policy every 100 ms and grants 500 ms worker leases; expiry kills the worker. This avoids relying on unavailable resource services inside isolated UIDs. The worker also caps sampled PSS at 384 MiB. Diagnostics cannot sit in front of its emergency stop. The app's database/Koin/runtime initialization is skipped in isolated processes. This spike is opt-in QA instrumentation, not a second production runtime owner or an enabled semantic-search feature. Inherited SDK network permissions are explicitly removed from QA and checked by instrumentation.

Cold/warm encoding, cancellation of an active repeated batch and fresh-process recovery are measured separately. No Gemma generation or personal input is used by this gate. The existing explicitly authorized QA Android-pressure profile may be selected; ordinary app thresholds remain unchanged. Failures remain in separate run-correlated reports. Passing this isolated encoder spike alone will not prove the complete five-second retrieval contract, native foreground handoff, indexing arbitration, semantic quality or the consolidated P2 campaign.

The host FlatBuffer audit found three dense token shapes of `[-1, 192]`, a 384,344-byte optimized SentencePiece configuration (SHA-256 `ab32418a9a7f2c0c95e3db6233f2fbd8243e2929a84cd5feec9c1b1ca615c420`), 8000 piece scores and a 60,382-byte normalization replacement table. This is not the Gemma tokenizer and not a SentencePiece ModelProto. The Gemma byte-bound proof cannot be reused. Neither the public embedder nor its provider exposes exact counting. Until a vetted counting bridge or a different verified encoder clears this gate, semantic adoption remains blocked. A lifecycle pass or a nonempty vector is not permission to accept silently clipped text. The metadata-only auditor uses pinned host dependencies via `bash scripts/audit-encoder.sh /path/to/the/public/model.tflite`.

References: [MediaPipe embedder guide](https://developers.google.com/edge/mediapipe/solutions/text/text_embedder), [versioned candidate](https://storage.googleapis.com/mediapipe-models/text_embedder/universal_sentence_encoder/float32/1/universal_sentence_encoder.tflite), [Google test-model provenance](https://chromium.googlesource.com/chromium/src/+/refs/tags/124.0.6367.150/third_party/tfhub_models/README.chromium).
